## 1. 当前已经确认的起点

2026-08-16 已在 24 V 关闭的条件下完成以下实机验证：

- Windows 已识别 `STM32 STLink`，USB ID 为 `VID_0483/PID_3748`。
- OpenOCD 识别到 Cortex-M4、1024 KiB Flash，目标电压为 3.261 V。

- 当前 `COM19` 已实测连接 PA9/PA10 的 USART1 二进制口，波特率为 115200。
- 3 秒零速度测试收到 287 个有效协议帧，`crc_errors=0`、`length_errors=0`、`version_errors=0`。
- 零速度时左右目标、实测速度、PWM、编码器和里程计速度均为 0，`fault_flags=0x0000`。
- 在 24 V 关闭时，以低于停转判定门槛的 0.02 m/s 完成实机看门狗测试，结果为 `PASS 500 ms command watchdog`；超时后 `fault=0x0001` 且左右 PWM 均为 0。

尚未由上述测试确认的项目包括：UART4 的实际接线、PWM 波形、每圈编码器计数、电机方向、24 V 带电运行、急停动态停机、负载 PID、里程计标定和长期 EMI 稳定性。

## 2. 安全边界和接口分工

### 2.1 不得跳过的安全条件

1. 逻辑调试、烧录、传感器、手转编码器和 PWM 示波器测试期间，24 V 必须关闭。
2. 首次打开 24 V 前，左右轮必须可靠悬空，底盘用支架固定，轮胎周围不得有人、线缆或工具。
3. 急停开关必须伸手可及；上位机必须能立即发送 STOP；24 V 回路必须有适当保险和总开关。
4. STM32、DAP/ST-Link、RK3576、5 V 传感器和两块 IBT-2 必须共地。
5. HC-SR04/CS100A 如果以 5 V 供电，Echo 到 PB6 前必须降压到不高于 3.3 V。
6. PC10/PC11 与板载 SD 卡 DAT2/DAT3 复用。使用 UART4 调试时不得插 SD 卡，也不得启用 SDIO。
7. 电机调试时停止 RK3576 的 `/cmd_vel` 发布器，避免 RK 命令覆盖电脑调试命令。
8. USART1 的 PA10 只能由一个 TX 驱动。RK、板载 CH340 和外接串口的 TX 不得同时连接 PA10。

## 3. 状态位速查

### 3.1 `fault` 控制故障位

| 位值 | 含义 | 处理原则 |
|---:|---|---|
| `0x0001` | 500 ms 命令超时 | 上电未收到命令或 STOP 后出现属预期；连续发送合法零速度可清除此位 |
| `0x0002` | UART 接收错误/溢出 | 检查电平、共地、波特率和干扰 |
| `0x0004` | CRC 错误 | 检查二进制协议、线缆和 EMI |
| `0x0008` | 协议长度/版本/格式错误 | 不要向 USART1 发送 ASCII；多数故障位会保留到复位 |
| `0x0010` | 左编码器跳变或停转 | 锁存停机，修复后按 NRST 复位 |
| `0x0020` | 右编码器跳变或停转 | 锁存停机，修复后按 NRST 复位 |
| `0x0040` | 发送队列溢出 | 检查串口吞吐和主循环阻塞 |
| `0x0080` | 10 ms 控制周期超时 | 停机，检查中断负载和阻塞代码 |
| `0x0100` | 非法速度命令 | 检查 NaN、参数和编码器锁存状态 |
| `0x0200` | 急停有效 | 立即 PWM=0、EN=0；释放后按本文流程人工复位 |
| `0x0400` | 安全联锁要求停机 | 当前默认未启用前障碍/台阶硬停 |
| `0x0800` | 传感器安全配置错误 | 联锁启用但对应驱动未启用 |

### 3.2 传感器状态位

| 字段 | 位值 | 含义 |
|---|---:|---|
| `valid` | `0x0001` | 左 ToF 有效 |
| `valid` | `0x0002` | 右 ToF 有效 |
| `valid` | `0x0004` | 超声波有效 |
| `valid` | `0x0008` | MPU6050 有效 |
| `sensor_fault` | `0x0001` | MPU6050 故障 |
| `sensor_fault` | `0x0002` | ToF 协议模式未确认 |
| `sensor_fault` | `0x0004` | 超声波协议模式未确认 |
| `sensor_fault` | `0x0008` | 左 ToF 超时/帧错误 |
| `sensor_fault` | `0x0010` | 右 ToF 超时/帧错误 |
| `sensor_fault` | `0x0020` | 超声波异常短脉冲或 ECHO 上升后卡高 |
| `obstacle` | `0x0001` / `0x0002` | 左/右台阶 |
| `obstacle` | `0x0004` | 超声波近障 |
| `obstacle` | `0x0008` / `0x0010` | 左/右红外触发 |

全部四类传感器正常时通常为 `valid=0x000F`、`sensor_fault=0x0000`。无效传感器显示的距离即使为 0，也不能解释为“目标距离为 0”。

## 4. 阶段 A：静态供电和短路检查（24 V 关闭）

### 操作

1. 断开 24 V 电机主电源，只保留 DAP/USB 和经确认的逻辑 5 V。
2. 用万用表确认 24 V 母线为 0 V，F407 3.3 V 轨约为 3.2～3.4 V，5 V 轨约为 4.75～5.25 V。
3. 测量所有模块 GND 与 F407 GND 连通。
4. 测量 PB6 Echo 高电平，任何情况下不得超过 3.3 V。
5. 上电静止时检查 PE8/PE10 EN 应为低，PE9/PE11/PE13/PE14 不应输出有效占空比。
6. 确认两块 IBT-2 的 24 V 电机端和 5 V 逻辑端没有接反。

### 期望结果

- ST-Link 能读取约 3.3 V 的目标参考电压。
- MCU 和传感器正常上电，无芯片异常发热、异味或电源反复重启。
- 24 V 关闭时电机绝不动作。

### 不通过时

任何电压越界、异常发热、PB6 超过 3.3 V、GND 未共地或电机意外动作，都必须立即断电排查，不得继续烧录或运动测试。

## 7. 阶段 D：UART4 可读调试口（24 V 关闭）

### 7.1 接线

- PC10 UART4_TX → DAP/USB-TTL RX。
- PC11 UART4_RX ← DAP/USB-TTL TX。
- GND ↔ GND。
- 只使用 3.3 V TTL；调试器的 5 V TX 不得接入 PC11。
- 拔出 SD 卡。

USART1正式链路不再经过电脑COM口或fireDAP虚拟串口，而是RK板载 `/dev/ttyS3`（稳定别名 `/dev/footbath_stm32`）。ASCII调试必须使用独立USB-TTL接PC10/PC11；没有该模块时可跳过UART4步骤，但不能把fireDAP TX/RX重新接回USART1。

如果串口在 MCU 启动后才打开，READY 可能已经错过，但仍应看到 `HELP`、`PARAM` 和 5 Hz 的 `TEL`。默认参数期望为：

### UART4 支持的命令

| 命令 | 期望响应/作用 |
|---|---|
| `help` | 返回完整命令列表 |
| `status` | 立即返回一行 `TEL` |
| `params` | 返回当前 PID、轮距、限速和 500 ms 看门狗 |
| `stream on` / `stream off` | 返回 `OK,stream=...`，开启/关闭 5 Hz 自动遥测 |
| `stop` | 返回 `OK,stopped`，PID 清零、PWM=0、EN=0 |
| `vel 0.05 0` | 返回 `OK,vel accepted; watchdog=500ms` |
| `wheel 0.05 0.05` | 返回 `OK,wheel accepted; watchdog=500ms` |
| `pwm 12 0` | UART4 专用开环占空比；PID 完全旁路，限幅 ±35%，仍受 500 ms 看门狗保护 |
| `pid both 0.05 0.001 0` | 先停机，再在 RAM 中修改 PID；复位后恢复源码默认值 |

单次 `vel`/`wheel`/`pwm` 只刷新一次 500 ms 看门狗。连续运动必须以约 20 Hz 重发，并在末尾 STOP，因此运动阶段应使用项目脚本而不是手工长按发送。`pwm` 仅用于轮子置空时严格测量开环死区，正常行驶仍使用 USART1 `CMD_VEL`。

## 8. 阶段 E：急停、状态灯和红外输入（24 V 关闭）

保持 USART1 零速度脚本或 UART4 监视器运行。

### 8.1 状态灯

- 无故障：PF6 红灯每 500 ms 翻转一次。
- 一般故障：每 250 ms 翻转一次。
- 左/右编码器故障或急停：每 100 ms 翻转一次。

这里的“翻转”是亮灭状态改变一次，完整亮灭周期是上述时间的两倍。

### 8.2 急停 PG4

1. 保持 24 V 关闭并持续发送零速度。
2. 按下急停，确认 PG4 被拉低。
3. 观察 `fault` 出现 `0x0200`，左右 PWM 为 0，PE8/PE10 为低，状态灯进入 100 ms 翻转。
4. 保持上位机停止，释放急停。
5. 按 NRST 复位，再重新发送零速度；确认 `fault=0x0000` 后才允许继续。

重要：当前固件在 PG4 为低时每个主循环都会硬停，并保留 `FAULT_ESTOP` 诊断位；但释放急停后，新速度命令并没有额外的“人工重新使能”软件闭锁。测试规程因此强制要求释放急停后先停止命令并按 NRST，不能把故障位保留误认为已经实现安全重新使能逻辑。

### 8.3 左右红外 PG2/PG3

1. 分别遮挡或触发左、右红外。
2. 左红外应使 `obstacle` 增加 `0x0008`，右红外应增加 `0x0010`；同时触发为 `0x0018`。
3. 移除目标后对应位应恢复。

当前 `FRONT_OBSTACLE_SAFETY_ENABLE=1` 只控制正前超声波，左右红外已拆分到 `IR_OBSTACLE_SAFETY_ENABLE=0`。因此 PG2/PG3 状态会显示，但不会让电机停车；超声波近障则会直接触发 F407 停车。

## 9. 阶段 F：板载 MPU6050（24 V 关闭）

MPU6050 的完整三轴值应从 UART4 `TEL` 查看；USART1 也发送正式 `MSG_IMU_RAW(0x06)`，但 `closed_loop_test.py` 的 CSV 不展开 IMU 六轴字段。

当前固件上电时会先恢复 I²C 总线，并在控制调度启动前静止采样约 1.5 秒，自动计算陀螺三轴零偏和加速度统一比例。每次上电或复位时必须保持底盘完全静止；若在此阶段移动底盘，必须静止后重新复位。

### 安装和静态检查

1. 板子应刚性固定在底盘上，尽量靠近旋转中心，明确记录板载 X/Y/Z 与车体前/左/上的映射。
2. 避开电机大电流线、IBT-2 和松动结构；允许薄层减振，但不应使用会让板子晃动的厚软泡棉。
3. 不得再并联地址同为 0x68 的外接 GY-521。
4. 静止 60 秒观察 `valid` bit3 应持续为 1，`sensor_fault` bit0 应持续为 0。
5. 静止时三轴加速度矢量模长应接近 1000 mg；重力落在哪一轴取决于安装姿态。
6. 静止角速度应接近 0。初步台架判据可用各轴绝对值通常小于约 50 mrad/s；最终必须做零偏和温漂标定。

### 动态检查

- `valid` 长期缺少 `0x0008`。
- `sensor_fault` 出现 `0x0001`。

| EMI 复测 | 电机启停、转向、传感器同时工作 | 30 min | CRC/格式错误为 0，ToF 丢帧率达标，IMU/I2C 不失联 |

## 19. RK3576 联调

1. USART1 保持 PA9/PA10、115200、8N1、3.3 V TTL 和共地。
2. 正式消息 `0x01～0x06` 与 RK3576 当前桥接协议保持不变；F407 额外发送的 `0x7F DEBUG_STATUS` 可由 RK 端安全忽略。
3. 先让 RK 持续发送零 `/cmd_vel`，确认 F407 `fault=0`、CRC 错误为 0。
4. 再让 RK 以不低于 2 Hz、推荐 20 Hz 发布低速命令，避免 500 ms 看门狗动作。
5. 验证停止 ROS 节点、拔掉 TX 或网络控制链断开后，F407 在约 500 ms 内独立停机。
6. 核对 `/odom`、IMU、距离状态、TF 坐标方向和时间戳；之后再进入 SLAM、AMCL 和 Nav2。
7. UART4 可以同时连接电脑观察全部数据，但不得同时从 RK 和 UART4 连续发送互相冲突的运动命令；最后收到的合法命令会刷新控制目标。

## 20. 常见问题定位

| 现象 | 优先检查 |
|---|---|
| OpenOCD `open failed` | ST-Link 是否枚举、VTref/GND/SWDIO/SWCLK/NRST、Keil 是否占用、降低 SWD 速度 |
| COM Access denied | SerialDebug/SSCOM/其他 Python 是否仍占用，正常关闭工具后重试 |
| USART1 显示乱码 | 二进制口的正常现象；用十六进制模式或 `closed_loop_test.py` |
| USART1 `frames=0` | 接错到 UART4、TX/RX 未交叉、GND、115200、旧固件、COM 号 |
| UART4 仍是乱码 | 实际接到了 USART1、波特率错误、5 V TTL、线路干扰 |
| `fault=0x0001` | 上电/STOP 后没有持续命令；合法零速度命令可清除 |
| `fault=0x0008` | 向 USART1 发了 ASCII 或帧格式错误；停止错误发送并复位 |
| `fault=0x0010/0x0020` | 编码器无脉冲、跳变、极性/线序或电机堵转；修复后必须复位 |
| `valid=0x000E, sensor_fault=0x0008` | 左 ToF 瞬时丢帧；查 PD5/PD6、921600、供电、共地、接插件和 EMI |
| `sensor_fault=0x0010` | 同上，检查右 ToF PD8/PD9 |
| `sensor_fault=0x0020` | PC0 无 Trig、PB6 Echo/分压错误、无目标、超量程或超时 |
| `sensor_fault=0x0001` | 板载 MPU6050/I2C、地址 0x68/WHO_AM_I 0x68 或 0x70、外接同地址冲突 |
| 电机不转但有 PWM | 24 V、IBT-2 5 V 逻辑、EN、共地、保险、输出端和电机线 |
| 电机方向或闭环方向错 | 分开验证 `MOTOR_COMMAND_SIGN` 与 `ENCODER_SIGN`，不要同时盲改 |
| 电机一开 ToF/串口就掉线 | 星形供电/地、退耦、屏蔽/双绞、信号线远离电机线、ToF DMA/IDLE 升级 |
