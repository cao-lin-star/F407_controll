# PS2无线手柄接线与底盘控制说明

> 适用工程：STM32F407ZGT6底盘  
> 接口方式：PA4～PA7软件SPI式协议，3.3V逻辑  
> 当前状态：代码和CubeMX已配置、Keil已编译通过；实际接收器通信与落地运动尚待硬件验收。

## 1. 接线表

| PS2接收器 | 接收器方向 | STM32F407引脚 | GPIO配置 | 说明 |
|---|---|---|---|---|
| VCC | 电源输入 | 3.3V | - | 推荐只使用3.3V，避免DATA输出5V |
| GND | 电源地 | GND | - | 必须与F407共地 |
| DATA / DAT / DI | 接收器→F407 | PA4 | 输入、内部上拉 | LSB优先的数据输入 |
| COMMAND / CMD / DO | F407→接收器 | PA5 | 推挽输出、默认高 | 主机命令数据 |
| ATT / CS / SEL | F407→接收器 | PA6 | 推挽输出、默认高 | 一帧通信期间拉低 |
| CLOCK / CLK | F407→接收器 | PA7 | 推挽输出、默认高 | 软件时钟 |
| ACK | 接收器→F407 | 不接 | - | 当前读取协议不使用 |
| NC | - | 不接 | - | 两个NC均悬空 |

接收器不同批次的插头方向可能不同，必须按接收器丝印确认DATA、CMD、CS、CLK、VCC和GND，不能只凭排线颜色判断。

## 2. 引脚冲突检查

PA4、PA5、PA6、PA7在当前CubeMX工程中此前均未分配。新增PS2接口后，仍与下列外设完全分离：

| 现有功能 | 引脚 |
|---|---|
| RK3576 USART1 | PA9、PA10 |
| DAP/UART4调试 | PC10、PC11 |
| 左ToF USART2 | PD5、PD6 |
| 右ToF USART3 | PD8、PD9 |
| MPU6050 I2C1 | PB8、PB9 |
| 超声波 | PC0、PB6 |
| 左编码器TIM2 | PA15、PB3 |
| 右编码器TIM3 | PB4、PB5 |
| 电机TIM1 PWM/EN | PE8、PE9、PE10、PE11、PE13、PE14 |
| SWD | PA13、PA14 |

CubeMX配置文件：`F407/Footbath_Chassis_F407.ioc`。

## 3. 通信参数

F407每25ms轮询一次，即40Hz。每次通信：

```text
ATT拉低
F407发送：01 42 00 00 00 00 00 00 00
接收典型：FF 73 5A BTN1 BTN2 RX RY LX LY
ATT拉高
```

协议特点：

- 8bit全双工；
- LSB最低位先行；
- CLK空闲为高；
- 时钟半周期4µs，名义频率约125kHz；
- 只有模式ID合法且第三字节为`0x5A`才算有效帧；
- `0x73`和`0x79`允许进入模拟手动驾驶；
- `0x41`、`0x53`只能确认连接，不允许输出运动速度。

## 4. 控制方法

| 操作 | 结果 |
|---|---|
| START短按 | 摇杆居中且R1释放时，进入或退出手动模式 |
| R1持续按住 | 手动模式下允许运动，并由PS2占用最高优先级控制权 |
| 松开R1 | 最迟一个25ms轮询周期内立即停车并释放PS2控制权 |
| 左摇杆上下 | 前进/后退，软件绝对上限 ±1.00 m/s；首次实车调试应以小行程限制在约 0.10 m/s 内 |
| 右摇杆左右 | 左转/右转，软件上限 ±0.50 rad/s |
| SELECT | 立即停车、取消手动使能并释放PS2控制权，同时设置重新使能锁存 |
| SELECT或外部STOP后按START | 摇杆居中、R1释放时解除锁存，仍不进入手动模式 |
| 再按一次START | 重新进入手动模式；只有随后按住R1才会占权和运动 |

START采用“释放后再按下”的边沿判定。上电、失联恢复或重新配对后，必须先松开START，再按下才会生效。

摇杆中心死区为±15个原始计数。PS2输出的是线速度和角速度，最终仍进入现有差速换算、双PID、编码器反馈和PWM限幅，不会绕过闭环直接控制电机。

## 5. 控制权与停车规则

优先级：

```text
硬件急停/障碍联锁/任一正式STOP
          >
PS2手柄
          >
UART4调试
          >
RK3576 CMD_VEL
```

- PS2只有在“链路有效、手动模式有效且R1正被按住”时才占有运动控制权；R1松开或SELECT仍会立即停车。
- PS2占权时，UART4和RK运动命令可被解析，但不得改变当前目标。
- R1松开后PS2立即释权；即使无线接收器在手柄关机后仍伪装成`0x73 + 摇杆中位`的合法帧，也不会阻塞UART4或RK的新命令。
- 连续100ms无合法PS2帧时立即停车，同时清除`manual_mode`并释放控制权。
- 释权不会恢复任何历史非零速度；随后UART4或RK必须送达一条新的、仍在租约内的命令才会运动。
- UART4的`vel`、`wheel`、`pwm`优先于RK，最后一条UART4运动命令的租约为500ms；停止刷新后RK的新命令可自动接管。
- 三路都不刷新时，F407在500ms内清除PWM并保持静止。
- RK正式STOP、UART4 `stop`、硬件急停或障碍联锁始终可以立即停车，并取消PS2手动使能；之后必须重新按START解锁/使能，PS2才能再次运动。
- 正常`cmd_vel`使用0.30m/s²加速和0.50m/s²减速斜坡；R1松开、失联、STOP及安全故障不等待斜坡。

## 6. UART4调试

UART4新增PS2字段：

| 字段 | 含义 |
|---|---|
| `ps2_link` | 1=最近100ms内通信有效 |
| `ps2_mode` | 手柄模式ID，模拟红灯通常为0x73 |
| `ps2_manual` | 1=PS2手动模式已使能；只有`ps2_r1=1`时才实际占权 |
| `ps2_r1` | 1=R1行驶使能被按住 |
| `ps2_stop` | 1=软件停车/失联停车已锁存 |
| `ps2_rx` | 右摇杆左右原始值 |
| `ps2_ly` | 左摇杆上下原始值 |

输入命令：

```text
ps2
```

返回示例：

```text
PS2,link=1,mode=0x73,manual=0,r1=0,stop=0,btn1=0xFF,btn2=0xFF,rx=128,ry=128,lx=128,ly=128,v_mm_s=0,w_mrad_s=0,valid=1200,invalid=0
```

健康目标：

- 配对后`link=1`；
- 模拟模式`mode=0x73`或`0x79`；
- 摇杆居中约127～128；
- 正常静止时`manual=0/1`均可，但`r1=0`时速度必须为0；
- 稳定通信时`invalid`不应持续快速增加。

## 7. 首次测试步骤

### 7.1 逻辑测试，24V电机电源关闭

1. 接收器只接3.3V、GND、DATA、CMD、ATT、CLK。
2. 打开PS2手柄并等待配对。
3. 按ANALOG切换到模拟红灯模式。
4. 复位F407。
5. UART4发送`ps2`，确认`link=1, mode=0x73`。
6. 分别推动四个摇杆方向，确认原始数值方向。
7. 按START，确认`manual=1`。
8. 不按R1推动摇杆，确认目标速度和PWM始终为0。
9. 按住R1推动摇杆，24V仍关闭，确认目标速度字段变化。
10. 松开R1，确认`source`立即不再为3；随后发送UART4 `vel 0.05 0`，确认返回`OK,vel accepted`。
11. 关闭手柄：若接收器能报告真实失联，应在100ms左右出现`link=0, manual=0, r1=0`；若接收器继续伪装成`link=1`，也必须保持`r1=0`且不得阻塞UART4/RK接管。
12. UART4发送`stop`后确认`ps2_manual=0`；PS2必须重新按START解锁/使能后才能再次运动。

### 7.2 轮子悬空测试

1. 架空底盘并准备硬件急停。
2. 开启24V。
3. START进入手动模式。
4. 按住R1，只轻推左摇杆向上。
5. 确认两轮均向前，编码器反馈均为正。
6. 松开R1，确认最迟25ms目标归零，随后EN关闭。
7. 轻推右摇杆左/右，确认原地旋转方向。
8. 运动中关闭手柄，确认最迟一个25ms轮询周期内因R1释放而立即停车、释权；随后UART4或RK发送新的低速命令应能重新控制。若接收器不报告真实断链，`link`可能仍为1，但`source`不得继续为3。

### 7.3 落地低速测试

当前PS2满摇杆线速度绝对软件上限为0.30 m/s、角速度上限为0.50 rad/s；摇杆仍按行程比例输出。落地测试必须先确认急停、R1松开停车、SELECT锁存、失联停车和RK/PS2仲裁。
